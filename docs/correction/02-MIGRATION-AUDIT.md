## Key Findings

1. **No `migration_lock.toml`** — Indicates `db push` was primarily used for schema management, not `migrate`.
2. **3 loose SQL files** — These are manually written migrations, not generated by `prisma migrate`. They are PostgreSQL-compatible but lack Prisma's checksum tracking.
3. **2 proper Prisma migrations** — These have the standard `migration.sql` format.
4. **Schema divergence** — The current `schema.prisma` has 122 models. The migrations cover only a subset. The majority of tables were created via `db push`.

## Production State
